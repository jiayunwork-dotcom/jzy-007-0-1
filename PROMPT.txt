做一个可独立部署的欧式期权 Black–Scholes 定价核算服务，让上游把合约参数交给它，算出理论价格与一阶希腊值，并能从市场价格反解隐含波动率。这是一个纯服务端的数值定价组件，不涉及下单、持仓、账户体系或任何前端页面。

定价：调用方给出标的现货价格 S、执行价 K、剩余期限 T（以年为单位）、无风险利率 r、波动率 σ、以及看涨或看跌方向；可选连续分红率 q，缺省按零处理。服务返回理论价格，以及定价过程中的 d1 与 d2。到期已经到来（T 恰好为零）时，不得再套用尚未到期的公式，必须直接返回内在价值：看涨为现货减执行价与零的较大者，看跌为执行价减现货与零的较大者。现货、执行价、波动率取非正值，期限取负值，都要在计算前返回带说明的结构化错误，指明哪个参数不合法。利率与分红率允许为零或为负（负利率场景），但必须是有限数值。

希腊值：同一组参数下还要给出 Delta、Gamma、Vega、Theta、Rho。看涨与看跌的 Gamma 必须相同，Vega 必须相同。在分红率为零时，看涨 Delta 落在闭区间零到一，看跌 Delta 落在闭区间负一到零；看涨 Delta 减去看跌 Delta 必须等于对平价关系求现货偏导后的结果。Theta 与 Rho 的符号必须与利率、剩余期限的比较静态一致：只把利率升高时看涨价格上升、看跌价格下降，对应的 Rho 看涨为正、看跌为负。

隐含波动率：调用方给出市场价格以及除波动率以外的全部合约参数，服务反解出使理论价格等于该市场价格的波动率。把解出的波动率再代回定价接口，得到的理论价格必须在钉死的相对容差内回到原市场价格。市场价格落在无套利界外时（看涨不得低于贴现后的内在价值、不得高于现货的分红贴现；看跌对称），要明确返回不可行，而不是给出一个无意义的波动率。市场价格恰好等于内在价值且期限为零时，隐含波动率无定义，同样按不可行处理。

必须守住的行为：同一组现货、执行价、期限、利率、分红率、波动率下，看涨价格减去看跌价格必须等于现货乘以分红贴现因子再减去执行价乘以利率贴现因子，并在钉死的相对容差内闭合。只把波动率加大、其余不变，看涨价格与看跌价格都必须上升。只把利率加大、其余不变，看涨价格上升、看跌价格下降。当现货等于执行价且利率与分红率都为零时，看涨价格必须等于看跌价格。期限为零且现货高于执行价时，看跌价格必须为零、看涨价格必须等于现货减执行价；期限为零且现货低于执行价时，看涨价格必须为零。把现货、执行价同时按同一正比例缩放，价格必须按同一比例缩放，隐含波动率保持不变。请预置一个可直接调用的算例：平值、一年期、中等波动率、零分红，看涨价格应与零点四倍现货乘波动率乘期限平方根同量级。

输入与异常：缺字段、非数值、非有限值、未知的看涨看跌方向、把看涨看跌写成互相覆盖的矛盾字段，都要返回带说明的可读错误，而不是算出一个看似正常其实错误的数，也不能直接崩溃。批量定价中某一组非法时，要指出是第几组、哪个参数的问题，其余各组照常返回结果。

服务能力：除单张定价与希腊值查询外，支持一次提交多组合约的批量定价，并把每次核算请求与结果持久化保存，供之后按条件查询历史记录。对外提供定价接口、希腊值接口、隐含波动率接口、批量定价接口、历史查询接口，以及一个回显当前容差与默认分红率配置的查询接口。服务需暴露基本运行状态供监控采集，且并发处理多请求时结果互不干扰、历史记录不错乱。

技术上用 Python 实现，基于 FastAPI 提供 HTTP 服务，持久化用数据库，提供 Docker Compose 一键构建并启动服务与其依赖。代码请合理拆分为多个模块/文件，定价、希腊值、隐含波动率、输入校验与持久化不要堆在同一个文件里。附带能验证上述核算规则的自动化测试，覆盖看涨看跌平价闭合、到期内在值、波动率升高则两边价格都升、利率升高则看涨升看跌降、平值零利率时两边价格相等、看涨看跌 Gamma 与 Vega 相同、隐含波动率代回定价能闭合、界外市价返回不可行、非法参数被拒、批量部分失败其余成功、历史持久化正确、以及并发多请求互不串扰。
